# Aduna handoff note

## What this is
Discord-style chat app: Node + Express + Socket.IO + Postgres on Neon (every record encrypted at rest by the server), React/Vite client.
Servers, channels, E2EE DMs, friends, profiles. See README.md for how to run (npm install, npm run build, npm start).

## Done and tested
- Edit/delete messages (author; server owner can delete channel messages), replies, reactions, SVG icons, centered + button.
- File/image/video/audio attachments (8 MB, 4 per message). DM files are encrypted in the browser.
- GIF search via GIPHY (set GIPHY_API_KEY). Uploaded GIFs animate.
- Custom emoji: upload with checks (type, size, 16-512 px, roughly square, name filter, duplicate detection, GIF cleaning),
  save someone else's emoji by clicking it, report (3 reports disable it), :name: autocomplete, use in reactions.
  Server tests for all of this pass (npm test).

- Call bar: calls now live in a bar docked on the right edge of the window (like Discord's side panel), not a floating popup.
  Incoming calls ring inside it (Accept / Decline); after pickup it shows the other person and you as two tiles plus
  mute / camera / share / hang up. The member list hides under 1500px wide while a call is open; on phones the bar drops
  down over the top of the page.
- Responsive UI (client/src/styles.css, "Responsive layout" block at the end; App.jsx holds showList / membersOpen):
  >1800px larger type and wider panels; 1051-1500px members list moves into a drawer while a call is open; <=1050px
  members list is a slide-over drawer (people icon in the channel header); <=720px phone layout: the channel/DM list and
  the chat are separate screens with a back arrow (like Discord mobile), the Friends page and chat get a back arrow too,
  dialogs become bottom sheets, ringing calls and expanded calls go full screen, a voice call is a slim strip you can
  expand. Short landscape screens (<=480px high) get a tighter header. Touch: tap a message to show reply/react/edit/
  delete, a Send button appears (Enter adds a new line on touch screens), the composer grows as you type, inputs are 16px
  so iOS does not zoom, safe-area insets are respected (viewport-fit=cover), and the keyboard does not pop up when you
  open a conversation. Ultrawide (>=1800px): message column and composer are centered at about 1180px wide so lines stay readable; GIF picker height shrinks on short screens. Checked in Chromium at 360x640, 390x844, 844x390, 768x1024, 1024x768, 1280x720, 1920x1080 and
  2560x1080 with no horizontal overflow. Not checked on real iOS Safari / Android Chrome.
- Receiving fixes: (1) GET /api/call/config was registered after the /api 404 handler, so it always 404ed and calls had no
  STUN server (calls only worked on the same network). Moved above the handler; the client also falls back to Google STUN.
  (2) A ringing call is no longer ended when the callee's socket disconnects; it is re-sent when they reconnect or reload
  and otherwise ends by the 45 s ring timeout. (3) Ring sound was silently blocked by the browser until the first click;
  audio is now unlocked on the first click/key. (4) While ringing, the tab title flashes and, if the tab is hidden and the
  user allowed it, a desktop notification shows. The app asks for notification permission once, on the first click.
- 1:1 voice/video calls in DMs (client/src/Call.jsx, call:* socket events in server/index.js). Tested with two Chromium
  browsers using fake camera and mic: ring, decline, accept, mute, camera off/on, adding camera mid-call, hang up.

- Emoji picker (client/src/EmojiPicker.jsx): full Unicode set (1,900+) with search, category tabs, skin tones, frequently-used row and your custom emoji; used for the composer and for reactions (bottom sheet on phones). Data file client/src/emoji-data.json is generated by client/scripts/make-emoji-data.mjs.
- GIF button is always shown. With GIPHY_API_KEY it has search + endless scroll (server /api/gifs takes offset and returns next); without a key the popup explains the setup. Tested the UI with stubbed GIPHY responses; never run against the real GIPHY from my sandbox.

- Profile customization: display name, username (changeable once every 7 days; enforced in PATCH /api/me, returns 429 + availableAt),
  up to 5 social links (http/https only, normalised server-side), profile picture as Letter / Aduna logo / uploaded Image, and
  hover-or-click overlays on the banner and picture in the editor preview. Friends page opens on All, sorted Online > Idle >
  Offline > Do Not Disturb, and clicking a friend opens the DM directly (client/src/Friends.jsx). Tests: server/profile-test.js.
  Not done: the profile popup (UserCard) still opens from member lists / message authors in servers.

- Attachments: max 20 MB; auto-deleted 14 days after upload, or 5 days if over 10 MB (ATTACHMENT_TTL_DAYS, LARGE_ATTACHMENT_TTL_DAYS, LARGE_ATTACHMENT_MB). Uploads are buffered in memory (Render free = 512 MB RAM), so many simultaneous 20 MB uploads could be tight; profile pictures are 500x500 (client/src/image.js AVATAR_SIZE, server maxDim 500). server/index.js
  expireOldAttachments() runs at startup + hourly, flags channel attachments `expired` and emits message:edited; DM files just 404
  and the client shows the same placeholder (files.js loadBlob, Attachments.jsx). Tests: server/files-test.js.
- Hosting: DONE. server/db.js now uses Postgres (`pg`) via DATABASE_URL (Neon). Startup is async (`await store.init()`, `ready` promise exported from index.js); store file/image functions are async. JWT secret is stored encrypted in the `meta` table unless JWT_SECRET is set. DB_ENCRYPTION_KEY is required when NODE_ENV=production. render.yaml + /healthz added; `trust proxy` is on. Cloudflare R2: DONE and optional. server/db.js keeps images/attachments in R2 when R2_BUCKET etc. are set (sealed bytes uploaded with aws4fetch; the Postgres row stays as an index with an empty `data` column; non-empty `data` means the bytes are in Postgres, so old rows keep working). Tested only against a local S3 stand-in (server/r2-test.js), not real R2. Files are still served through the app (no signed URLs yet), so Render carries the download traffic. Storage cap: STORAGE_LIMIT_GB (default 9) enforced in db.js checkRoom() using a `size` column on images/files; throws code STORAGE_FULL -> HTTP 507 via the Express error handler. Counts only rows whose bytes are in R2. Tests need TEST_DATABASE_URL (they use a temporary schema). Single instance only (data cache is in memory).

- Server settings + server themes: owner-only screen (client/src/ServerSettings.jsx, opened from the server name menu) for name, icon (256px), banner (960x320) and theme ({ dark, bg, accent }). Server side: PATCH /api/servers/:id (name, theme), PUT/DELETE /api/servers/:id/icon|banner; server records gain iconImage, bannerImage, theme and serverView returns them; replaced images are deleted, referencedImages() keeps them, and members get the change live through server:update. The fade: styles.css registers every palette variable with @property and transitions them on :root; themes.js setServerTheme() swaps in the server palette while a server page is open (App.jsx effect), and everyone can opt out in Appearance (serverThemes in the saved theme). The owner sees a live preview of the draft theme while editing. Tests added to server/smoke-test.js; checked in Chromium (fade samples mid-transition, cancel reverts, DM page returns to the person's own theme, opt-out, 390x844 phone with no horizontal overflow). Not done: a theme for DMs, the dark-theme look of the black Aduna logo on the home button.

   device picker (mic/camera/speaker).

2. Tested against a local PostgreSQL 16, not against Neon itself (sslmode/channel_binding connection strings are handled by `pg`, but the first real deploy is the check). Known small race: two simultaneous sends of the same uploaded file id could both attach it.
3. No per-user storage quota for attachments. No NSFW image scanning for emoji (name filter + reports only).
